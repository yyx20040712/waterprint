## 1. 缺陷清单（根因·证据·修法）

### A-1【webapp-calc】提交计算不拦截未提交参数草稿（R2-P1-3 收敛第二步）

- **现象**（15 万吨 v1 实录，`.workflow/e2e-150k-2026-09-25/p150k-report.json`
  c44 步）：参数面板填完 8+8 项 → 工具条「保存」（toast 已保存）→「提交
  计算」→ 任务 failed `InvalidNodeError: municipal_input 缺必需参数
  ['kz','q_avg_daily']`。用户视角：每步都有成功反馈，最后一步裸失败且
  报错不指路。
- **根因**：参数草稿是 ParamForm 本地态，唯一正门=参数面板「提交重算」
  （apply）。E2E-2 批已给**保存按钮**挂徽标（`canvasEditToolbar.tsx:219`
  消费 `paramsStore.draftHint[projectId]` 计数），但**提交计算入口无闸**。
- **修法**（批 R1）：`runCalc` 起点读同一 `draftHint` 计数——非零时
  拦截+messageApi 明确指引（「参数面板有 N 项未提交——请先在参数面板
  点『提交重算』（工具条保存不携带参数草稿）」），不静默放行也不代提交。
  可选加分：提示 action 按钮「去参数面板」（选中最后编辑节点）。
- **回归锚**：vitest「draftHint>0 时 runCalc 不发 mutate 且出提示」
  「draftHint=0 照常提交（既有 T5 场景不回归）」；无头步「填参不提交→
  点提交计算→拦截提示出现」。
- **注意**：拦截文案必须诚实指路（现有正门语义），禁自动 apply（参数
  语义决策属用户——apply 会触发重算，静默代做=越权）。

### B-1【chat】首轮竞态 502 误导（fix-plan P1-2 遗留未闭环）

- **现象**：发首条消息 POST 200（任务异步）→ ChatPanel 立即 GET
  messages → 会话文件未落盘 502 → 固定文案「会话读取失败（中继不可达）」
  ——误导用户以为服务坏了。
- **修法**（批 R2）：history 查询失败且会话刚创建（本轮 POST 返回的
  session_id）时改退避重试（500ms×3 指数），仍失败则文案区分「会话
  尚未落盘（稍候自动刷新）」与「中继不可达」两种态。
- **回归锚**：vitest mock 502→200 序列断言重试+文案分支。

### B-2【sse】永不成流无终态兜底（fix-plan P1-4 遗留未闭环）

- **现象**：`useTaskEventSource` 退避达限转 60s probing 后永不
  invalidate——若 SSE 因代理/防火墙永不成流，面板永远「进行中」。
- **修法**（批 R2，与 B-1 同批同域）：probing 态叠加 TaskStatus 轮询
  兜底（probing 周期内 fetch 一次任务状态，终态即 invalidate）；或
  probing 超 N 轮（如 5×60s）降级提示「实时通道不可达——已切换轮询」。
- **回归锚**：vitest「SSE 永远 error→轮询兜底达终态」用例。

### B-3【core】孤立单元警告（R2-P2-2——E2E-5 回退件组装）

- **诉求**：19 节点 0 边「结构校验通过」零提示——validate_design_structure
  增孤立单元警告（⑦甲呈报不阻断；内置 kind 节点豁免）。
- **现状**：实现草稿全备（`.workflow/e2e-fix/E2E-5/isolated_warn.draft.md`
  ——validate_design_structure 尾部插入代码）；两阻断：锁定测试
  `core/tests/app/test_validate_design_structure.py` 精确断言冲突
  （更新=[HUMAN-LOCK]）+ ruff PLR0912 分支 17>12（需抽
  `_isolated_unit_warnings` helper）。
- **修法**（批 R3）：实现侧 AI 完成（源码非锁面：helper 抽取+插入+
  分支预算合规）→锁定测试期望更新**起草为完整 diff**（追加警告断言）
  →呈人类锁面笔。**组装完成后先跑 core 全量+快照确认仅预期红**。

### C-1【server-deploy】uvicorn 直启面启动校验收敛（E2E-1 欠账②）

- **现状**：`validate_data_packages` 只挂 `python -m` 入口；Docker CMD
  （uvicorn 直启）与运维直启绕过校验——镜像缺包/卷遮蔽时退回请求期 500。
- **修法候选**（批 R4 内先呈方案再动，位阶=设计裁量）：
  1. `deploy/Dockerfile.server` CMD 前置 entrypoint 脚本（python -c
     校验再 exec uvicorn）——部署面收敛，零代码面变化；
  2. main.py 模块级校验钩子（uvicorn 导入即触发）——覆盖面最广但
     conftest 的 create_app 面会炸（tmp data_dir 无四包），须配
     env 逃生门（如 `WATERPRINT_SKIP_DATA_VALIDATE=1` 仅供测试）。
  **倾向方案 1**（方案 2 引入测试逃生门=新配置面+新欠账）。
- **回归锚**：方案 1=Docker build 冒烟（本机无 Docker 则 CI 侧）；文档
  deployment.md 同步勘正。

### C-2【server】no-store 全 GET 面普查（round2 R2-P2-1 建议）

- **现状**：仅 `read_project` 补了 no-store；列表/枚举分页/任务状态等
  读面同病可复现（浏览器启发式缓存旧读）。
- **修法**（批 R4）：全 GET 数据读面统一——建议中间件面（`main.py`
  request_id 中间件旁并列，GET+`/api/` 前缀→`Cache-Control: no-store`），
  静态豁免（units 目录面若含不变资产可留缓存——本批全禁最简，豁免留
  后续按需开）。
- **回归锚**：server pytest 既有面零回归+新断言（任一 GET 响应头在场）。

### C-3【server】manifest 内容校验（k1 单审 W 级纵深建议）

- **修法**（批 R4）：`validate_data_packages` 的 is_file 判据升级为
  「存在且可解析出至少一条非空映射」（yaml.safe_load 非空 dict）——
  空/损坏文件启动即拒。错误文案区分「缺文件」与「文件空损」两态。
- **回归锚**：草稿用例（E2E-1 草稿面补两分支：空文件/损坏 yaml）。

### C-4【scripts】check_model_names 假绿基因（k1 单审 W1/W2）

- **修法**（批 R5，小批分级裁量——1 文件 ≤10 行两处）：①scan_file
  OSError 计数进汇总行（`[WARN] N 个文件读取失败`，不 FAIL）；②
  SCAN_DIRS 目录 is_dir()=False 由静默 continue 改为 FAIL（目录漂移
  绊线——整张源码面空扫是最该尖叫的场景）。
- **回归锚**：机检矩阵（根/非根 CWD×干净/正探针×目录改名探针）。

### C-5【webapp-chat】失败横幅无 error 明细（E2E-3 挂账）

- **修法**（批 R2，与 B-1/B-2 同批）：终态 failed 横幅消费任务状态面
  （turnStage 终态回调补 fetch TaskStatus 取 error 摘要，或 SSE 事件
  载荷扩 error 字段——设计裁量：**倾向前端补查**，零协议破面）。
- **回归锚**：vitest「failed 轮横幅含 error 文本」。
