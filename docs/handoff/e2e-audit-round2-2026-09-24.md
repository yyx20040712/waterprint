## 0. 执行摘要

按用户剧本完整走了一遍「从零建厂」：**清空全部项目 → UI 空白建项 → 单元库逐个添加 19 个
工艺单元 → 拖拽连 17 条边 → 逐节点输入自设参数（进水 5 万 m³/d、kz1.35、COD380/BOD190/
SS240/NH3N 32/TN42/TP5.5 + 7 个单元 8 处参数改动）→ 校验保存 → 参数面板「提交重算」×8 →
九个结果面板逐一查看 → 工程口径业务核对 → 改数复算两轮（规模×1.6、进水氨氮+40%）**。

**结论分两面**：
- **计算内核的业务正确性：优秀**——所有能手工复算的量全部吻合（水量闭合精确、HRT=V/Q、
  需氧量分解恒等式闭合、污泥链条质量守恒、电耗碳排 opex 逐位可复算、规模缩放十项趋势全对、
  警告体系带规范出处与调节方向）。
- **UI 从零搭建链路：能走通，但坑多**——本轮新抓 1 个 P0（三维视图对 UI 建项必 500）、
  4 个 P1（节点被小地图遮挡不可点、参数保存语义陷阱、进水物理约束缺失、HTTP 缓存旧读）、
  若干 P2；另确认第一批 antd 告警群仍在。

## 3. 第二轮新发现缺陷（增量清单）

> 第一轮四大 P0（data_dir CWD/只读提交计算 no-op/聊天桥 repo 推导/聊天锁死）未在本轮
> 复测面内（本轮全程健康环境+编辑态/apply 通道），**仍然在册待修**。

### R2-P0-1【三维视图】UI 添加的内置进水节点不在 UF-32 对照表 → 场景 500

- **现象**：`GET /api/scene/{project}` → 500 `InvalidGeometryError: 单元 'municipal_input'
  不在 UF-32 对照表`；三维视图面板错误态（canvas=0）。**凡经 UI「添加到画布」建进水节点的
  项目，三维视图必死**；导入 golden（节点键=`inlet`）不受影响——第一轮阶段2 三维能出图正因如此。
- **根因链**：`webapp/src/features/canvas/lib/designWriter.ts:77` addUnit 对 builtin 用
  catalog unit_id（`municipal_input`）作节点键（值带 kind 自描述→引擎装配认 kind→计算/校验全通）；
  但 `core/waterprint/geometry/pools.py:93 _projection()` 按节点键查 UF-32 表——表内只有
  `inlet` 行。**装配语义（认 kind）与三维取数语义（认键）双口径不一致**。
- **修法建议**（修复会话二选一，建议后者）：
  1. UF-32 表补 builtin 行（municipal_input/junction/quality_edit/recycle_junction 各自映射，
     且含 `_2` 实例键面——枚举不可控，治标）；
  2. **scene 装配按节点值内 kind 映射**到几何行（与引擎装配同口径——治本，一处改动）。
- **回归锚**：UI 建项（含进水节点）→ `GET /api/scene` 200 → 三维视图出模型。
- **测试落点**：server 侧（锁面 [HUMAN-LOCK] 工序）+ webapp 无头步。

### R2-P1-1【画布遮挡】节点卡片被小地图/单元库面板盖住 → 无法选中

- **现象**（本轮高密沉淀池两次复现，Playwright 命中报告原文）：`minimap-svg subtree
  intercepts pointer events`；平移后换成 `<aside>（单元库）subtree intercepts`。真实用户
  表现：反复点某池子没反应=「软件坏了」。
- **根因**：自动折行布局不管 UI 覆盖区（右下 Controls/小地图、左侧 Sider）；React Flow
  覆盖面板 z-index 高于节点。
- **修法建议**：①自动布局活动区避开画布右下 200×150 与左缘（layout 计算扣 padding）；
  ②或缩小后仍被盖的节点点击由 minimap 导航补救——文档化。至少 ①。
- **顺手**：画布「全图适配」是用户自救手段——建议编辑态进入时自动 fitView 一次。

### R2-P1-2【连线暗坑】视口外句柄拖拽静默落空（用户视角=连线失灵）

- **现象**：19 节点默认视图下 17 条拖拽**全部无效果、无提示、校验还通过**（phaseA 实录：
  edges_after=0）；先点「全图适配」后 17/17 成功。
- **定性**：React Flow 语义使然+无引导。真实用户在未 fitView 状态连线=大概率同坑。
- **修法建议**：①新节点添加后自动 fitView/平移到新节点；②编辑态首次进入自动 fitView；
  ③（可选）拖拽落空 toast 提示「目标在视口外」。

### R2-P1-3【参数保存语义陷阱】工具条「保存」不携带参数草稿

- **现象**（本轮实录）：参数面板填 8+8 项 → 点工具条「保存」→ toast「已保存」→ 重开项目
  **参数全部蒸发**（design dump 全空）。参数唯一正门=参数面板底部「提交重算」
  （`POST /api/calc/solutions/apply` 原子应用+自动重算——服务端语义正确且强大）。
- **根因**：参数草稿是 ParamForm 本地态（collectParamChanges→apply 通道）；canvasStore
  会话四面（节点/边/位置/受检）不含参数草稿；`draftProjectRaw` 自然不带。
- **修法建议**（产品层，最低成本顺序）：①参数面板有未提交草稿时，工具条「保存」按钮加
  徽标/提示「参数需在参数面板提交重算」；②或「保存」时一并触发参数面板 apply；
  ③文档+空态引导写明双通道。**至少不能再让「已保存」toast 在参数未提交时出现**。
- **附带疑点**：切换节点时 ParamForm 草稿是否丢失未隔离验证（本轮全部即时 apply）——修复
  会话顺手核（若丢→再升一级）。

### R2-P1-4【进水物理校验缺失】NH3N>TN 静默接受

- **现象**：进水 NH3N=45、TN=42（组分大于总量，物理不可能）——校验通过、计算照跑、无警告。
- **修法建议**：validate/apply 前置域检 `NH3N ≤ TN`（同理 BOD5≤CODCr、各浓度≥0、q>0、
  kz≥1）；违例=422/校验报告红项。落点：core validate_design_structure 或 server 层
  （建议 core——CLI 同享）。
