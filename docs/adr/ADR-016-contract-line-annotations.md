# ADR-016：file-contracts 行数注记数字生成化（既有注记就地刷新）

- 状态：**Accepted**（授权链=深度审计建议 B1「file-contracts 的『N 行』
  注记由脚本生成整列，消灭 9 处漂移类问题」→总控裁决《审计裁决与
  治理优化规划_GLM5.3.md》B-4 纳入 P1 路线图→GOV4 批 2026-09-12）。
- 背景：
  - `docs/file-contracts.md` 表内「N 行」注记（现 29 处：core 1 +
    server 28）记录文件行数——多数标记预算压力（如 worker.py 498 行、
    exports.py 384 行）。B17 机器断言（N14-A2 G1-05）实测**手工注记
    脱钩 9 处**后，check_file_budgets 增注记一致性面（fail-closed）。
  - 一致性面把漂移变成门禁红，但**修复动作仍是手工编辑文档**：每次
    行数变化（重构/拆件常态）都强制一次 file-contracts.md 手改——
    治理文档成为最热修改对象（审计 §1 实测 113 次修订）的具体面。
- 决策：

| # | 决策 | 理由 |
|---|------|------|
| D1 | **注记数字段=生成物**：`scripts/gen_contract_lines.py` 把既有注记的数字重写为实体文件实数（幂等）；行数变化后的工序=跑生成器，不再手改数字 | 数字是实体的派生数据，手抄必漂（9 处实录）；幂等由「重写为实数」构造性保证 |
| D2 | **注记在场/缺席仍人审语义决策**：生成器只重写既有注记，不给无注记行新增、不删既有注记 | 哪一行值得标记预算压力是语义判断（非派生数据）；自动全员注记=噪声面，违背「登记面熵减」本意 |
| D3 | **解析与行数口径单源=check_file_budgets**：生成器 import 其 `_ANNOTATION_RE`/`_line_count`（同目录 import 先例=gen_same_layer_edges→check_module_graph） | 两套解析必漂（same_layer_lib 设立动机同款）；校验端/生成端同口径 |
| D4 | **忘跑检测器=既有注记一致性面**（零新门禁）：check_file_budgets 漂移即红，修复=跑生成器 | 检测器已存在且在册（B17）；B1-2 只把修复动作从手改文档换成跑命令——门禁数不增 |

- 后果：
  - 正面：行数注记从「每次行数变化强制手改文档」降为「跑一条命令」；
    file-contracts.md 的特性内修订次数预期显著下降（审计 B1 验收项）。
  - 代价：gen_contract_lines.py 新件登记（file-contracts §4）。
  - 首跑实录：29 处注记全吻合（GOV3 批尾状态新鲜）零改写；变异测试
    注记 262→263 即门禁红、生成器改写 1 处还原、复绿零字节残留
    （git diff 空）——检测器→生成器闭环双向验证。
