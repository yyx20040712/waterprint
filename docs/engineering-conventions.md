# 工程惯例（规格沉默处的默认答案）

> 业务逻辑本征复杂度高，规格不可能穷举——实现者在"规格沉默处"自由发挥，
> 就是未定义特性的孵化器。本文档把软件工程常识**项目化内化**为可执行惯例：
> 规格没写的地方**沉默即按惯例，不自创**。
> 上位文件：`AGENTS.md`（宪法）；惯例是"默认答案"不是新规格——**与既有规格
> 冲突时以既有规格为准**，冲突在 `undefined-features-register.md` 登记。
> 条目格式（一条一理由一绑定）：

```
### GR-xx <一句话惯例>
- 规则：<可执行的判定句>（【已拍板】条目逐字落地，不得改义）
- 为什么：<违反的真实代价，本项目语境>
- 绑定：<既有门禁/规格条款引用，或"本条新增——填补 <场景> 沉默">
```

## 1. 数值语义

### GR-01 确定性与数值正确性断言分层
- 规则：【已拍板】数值正确性断言与确定性断言分层：确定性=同输入双跑**字节级
  相同**（CI 常驻，绝不容差）；数值正确性=golden/手算对照用
  `pytest.approx(rel=1e-9, abs=1e-12)` 基准容差，个别量表（如高程 mm 级）
  在对照表内另注明更宽容差。
- 为什么：给确定性断言加"小容差"= 给不确定性留后门——双跑 diff≠0 就是回归，
  容差会吞掉序列化键序/求和序类 bug；golden 对照用绝对相等则把 pint 换算的
  末位抖动误报成失败，两掺后两类测试都失去信号。
- 绑定：AGENTS §6（双跑 diff=0、incremental==全量字节级常驻）既有；
  graph/executor.py R3、graph/incremental.py R1；本条新增——
  `pytest.approx` 基准容差值与"对照表内另注明"载体填补测试写法沉默。

### GR-02 NaN/±Inf 政策：输入拒绝、运算产生转领域异常
- 规则：【已拍板】NaN/±Inf 政策：**输入即拒绝**（parse/构造处领域异常）；
  运算产生（0/0、溢出）=求值器/compute 内转领域异常上抛；
  禁止 NaN 参与比较/静默传播。
- 为什么：NaN 参与比较恒 False，会顺着守恒断言一路"假合格"流进出水裕度
  （margin 对 NaN 永不告警）——静默传播的 NaN 是旧系统"算出 NaN 照样出图"
  事故的复发路径。
- 绑定：本条新增——各规格头只列领域异常类型未写 NaN 处置（如 propagate.py
  汇流 ΣQi=0 时 0/0、expr.py R5 只到"原生异常上抛由宿主决定包装"）；
  contracts/quantity.py R3（边界拒绝）为其输入侧既有样例。

### GR-03 舍入分层：计算不舍、序列化定点、整数化显式 ceil
- 规则：【已拍板】舍入分层：计算层**不舍入**；序列化 `round(x, 10)`
  （宪法 §8 已有）；显示层舍入属 i18n/UI 层不在内核；池数/格数等整数化
  一律显式 ceil 并写明依据（旧系统"两步 ceil"教训：栅槽长先算总长再
  ceil 台数）。
- 为什么：中途舍入把误差放大进下游（池数先 ceil 再算停留时间，两步 ceil
  会多配一整台设备）；显示层舍入进内核则换显示精度=改计算结果。
- 绑定：AGENTS §8、project/io.py R1、contracts/result_schema.py R3
  （round(x,10) 定点）既有；本条新增——"整数化一律 ceil 并写明依据"
  填补池数/格数/台数类参数圆整规则沉默。

### GR-04 物理量非负不变量：负值拒绝、Q=0 合法
- 规则：【已拍板】物理量非负不变量：流量/浓度/几何量为负=领域异常
  （守恒性质测试守护）；Q=0 是**合法输入**（照常计算，产出守恒一致的
  零系结果），与"负值拒绝"区分。
- 为什么：把"零流量"当非法会误杀合法工程态（汇流某支流 Q=0、检修工况
  n−1 池）；把零和负混为一谈则守恒断言口径漂移——零系结果必须仍满足
  Σ流出=Σ流入，这是它进性质测试的唯一方式。
- 绑定：contracts/quality.py R2（浓度非负）、business-logic.md §3 守恒
  断言点既有；**厂界 WaterFlow 构造仍按既有规格 flow.py R2（q_avg_daily>0）
  执行**——Q=0 合法语义适用于图内传播与单元计算路径；该口径分界已在
  undefined-features-register 登记（UF-03）。

### GR-05 浮点换算只经 pint，手写系数=评审拒绝
- 规则：一切单位换算只经 contracts/quantity.py 的 pint 包装；代码出现手写
  换算系数（如 `q / 86400`、`x * 0.001`）= 评审拒绝——反例即"手写
  1/86400 系数"，86400 这类数只允许出现在测试期望值里。
- 为什么：手写系数是魔法数字门禁漏网的高发区（AGENTS §3 白名单之外），
  且 86400/86400.0 的隐式整除与精度差异当年直接造成 Q_design 双轨病灶。
- 绑定：AGENTS §3 单位规则（ADR-002）、quantity.py R2 及【禁止】节、
  scripts/check_magic_numbers.py 既有。

### GR-06 参数范围默认闭区间，开区间必须显式声明
- 规则：manifest ParamSpec 的"范围"默认闭区间（min/max 端点合法）；
  需要开区间必须在范围元数据显式给严格算符；边界测试按此取
  min−ε/max+ε 两侧用例（GR-13）。
- 为什么：物理可行域几乎总含端点（kz=1 合法、池数≥2 含 2、停留时间=下限
  仍可校核）；实现者自创开区间会把合法方案挡在枚举之外，且这种错在
  pass_matrix 上不可见——可行解悄悄变少。
- 绑定：本条新增——填补 contracts/manifest.py ParamSpec"范围（可选，
  约束层消费）"的端点语义沉默；solution/constraints.py DSL（</<= 分立）
  为其执行载体。

### GR-07 浮点判等禁裸 ==（位级比较与近似比较二分）
- 规则：测试与断言中浮点值判等禁裸 `==`；确定性验证用字节级/位级比较
  （GR-01），数值正确性用 `pytest.approx`（GR-01 基准容差）；仅 0/±1 与
  索引类精确值允许 `==`。
- 为什么：`assert x == 0.3` 依赖实现路径的舍入巧合，重构求和序（合法变更）
  会让它假红，团队很快学会删断言——测试资产就是这样流失的。
- 绑定：本条新增——AGENTS §6 未写测试侧判等口径；expr.py 求值器布尔
  Compare（==）仅用于工况映射条件，不承担数值判等。

## 2. 错误处理

### GR-08 领域异常与程序缺陷二分
- 规则：可预期业务失败（非法参数/无解/不收敛）= 领域异常或 Result 风格
  返回；程序缺陷（不可能态、违反内部不变量）= 裸 assert / 让它崩溃，
  **不捕获不包装**。
- 为什么：给不可能态套领域异常，等于把 bug 翻译成"用户可自行调参解决"的
  诊断建议——误导用户去调一个不存在的参数；且吞掉栈迹后根因不可复现。
- 绑定：AGENTS §3（禁裸 except、可预期错误走领域异常）既有；本条新增——
  补"什么时候**就该**用 assert"的判定边界（规格头只写了前一半）。

### GR-09 异常消息规范：三元上下文 + 进发布即冻结
- 规则：【已拍板】异常消息规范：必须含 unit_id/condition_key/参数键三元
  上下文；**消息文本是计算迹的一部分，进过发布即冻结**（改文本=破坏审计
  可比性，等同 formula_id 稳定规则）。
- 为什么：无上下文的异常到 UI 只剩"计算失败"，诊断面板（business-logic
  §4）无从定位；改消息文本则跨版本的计算迹 diff 全线飘红，审计对照
  （M4 验收）失去可比基线。
- 绑定：本条新增——规格头只定义异常类型未定义消息契约；graph/executor.py
  R5（异常携带 unit_id 上下文上抛）、io.py R3（错误消息指明路径）为其
  部分既有落地；GR-20（稳定标识）为其演进侧锚点。

### GR-10 捕获后三选一，记录后继续=禁
- 规则：捕获异常后只有三种合法去向：转换为领域异常上抛 / 记录后按语义
  失败 / 顶层统一处理（server 层 exception handler）；"记条日志然后继续跑"
  = 禁止。
- 为什么：记录后继续= 半截结果带病发布——例如某支流混合失败被跳过，
  出水浓度直接缺失却仍出达标裕度，这是 business-logic §8"裸警告"之外
  更危险的静默失败形态。
- 绑定：AGENTS §3（禁错误静默通过、内核禁抛 HTTP 语义、server 统一
  exception handler）既有；trace/collector.py R3（采集失败=执行失败，
  宁可失败不可无迹成功）为同构既有样例。

### GR-11 异常类命名三族，禁新建同义异常类
- 规则：异常类命名只用三族——`Invalid*`（输入非法）、`*Divergence`
  （数值不收敛）、`*Conflict`（规格/配置矛盾）；已有语义等价类时新建
  同义异常类 = 评审拒绝。
- 为什么：同义异常类繁殖后，server 层映射表、诊断建议、测试断言都要
  逐类枚举——漏一类就是"某类失败对用户不可见"；三族之外的第一反例
  应先问"这真是新语义还是现有语义换皮"。
- 绑定：AGENTS §3（InvalidUnitConfig/LoopDivergence 等领域异常族）、
  contracts/flow.py R2（InvalidFlowError）、graph/loop.py R2
  （LoopDivergence）既有；本条新增——归类判定规则。

### GR-12 转换领域异常必须保留异常链
- 规则：在边界把底层异常转换为领域异常时必须 `raise ... from exc`
  保留原异常链；禁止裸 raise 丢栈。
- 为什么：领域异常是给用户的语言，异常链是给开发者的语言——丢链后
  "InvalidUnitConfig: 参数非法"之下三层真因（pint 量纲错/键名错）
  不可见，只能靠复现猜。
- 绑定：contracts/expr.py R5（异常链保留原 SyntaxError）既有样例；
  本条新增——推广为一切转换点的硬规则。

## 3. 边界与退化输入

### GR-13 数值参数边界测试清单（包内自查基线）
- 规则：每个数值参数必测七点：min / max / min−ε / max+ε / 典型中值 / 0 /
  负值（拒）——写入包内测试的自查基线；ε 取量纲合理小量并注明。
- 为什么：规格头写"非法构造拒绝"却不写测什么值，实现者只测手头那个
  非法值——恰好是负号位置不同的另一个数；七点清单让"拒绝路径"与
  "端点合法"（GR-06）同时被锁。
- 绑定：AGENTS §6 测试纪律、contracts/flow.py 测试要求（kz=1 合法）、
  quality.py 测试要求（负浓度拒绝）为既有样例；本条新增——模板化清单。

### GR-14 空集语义三态：合法 / 单位元 / 显式异常
- 规则：空图合法（M0 验收既有）；空序列聚合 = 返回单位元或抛显式领域
  异常（**写明选哪个**，禁"碰巧返回 0/None"）；单元素 = 最简非平凡
  用例，必须有用例覆盖。
- 为什么：空序列求和、单元素 min/max、空图执行是最容易写出隐性假设的
  三处——不写明选择，下一个实现者会做出相反选择且测试全绿。
- 绑定：M0 验收（空图合法）、contracts/condition.py 测试要求（空受检
  集合=仅基线两档）既有；本条新增——"单位元 or 异常须显式声明"门槛。

### GR-15 无隐式默认值，缺省必须显式且带出处
- 规则：参数缺省不存在"代码里顺手补一个"——默认值必须显式来自
  manifest（ADR-009）或 assumptions 清单，且带出处（norm_refs/来源
  字段）；两处皆无 = 领域异常。
- 为什么：隐式默认是"102.0m/3.0m/0.2m/4000 散落各处"病灶的复活通道，
  也是数值字面量门禁（AGENTS §3）绕行的常见姿势。
- 绑定：AGENTS §3（禁默认单位——本条是其向一切参数缺省的推广）、
  registry/assumptions.py R1/R2（无出处不准入库）、contracts/manifest.py
  R1d（norm_refs 非空）既有。

## 4. 确定性与迭代序

### GR-16 禁直接迭代 set 构造产出
- 规则：【已拍板】禁直接迭代 set 构造产出（Python set 迭代序不稳定）；
  需稳定序先 `sorted()`（键含中文时用 `sorted(key=repr)` 规避 locale）；
  dict 依赖插入序可以但**跨进程落盘前必须键排序**（宪法序列化规则的
  具体化）。
- 为什么：set 迭代序跨进程/跨 PYTHONHASHSEED 可变——同一 design 双跑
  字节级相同（executor R3）会在 Windows 开发机绿、CI 红且不可复现；
  中文键的 sorted 在不同 locale 下排序不同，repr 键把顺序钉死在代码里。
- 绑定：AGENTS §8（序列化确定性）、project/io.py R1（键递归排序）、
  solution/diagnose.py R1（乱序约束同报告）既有；本条新增——set/中文
  键两条执行细则。

### GR-17 计算路径禁时钟与随机；测试随机必须定种局部实例
- 规则：禁 `datetime.now()` / `random` / `time` 于计算路径（宪法既有）；
  种子随机用于测试（hypothesis/性质测试）必须 `random.Random(fixed_seed)`
  局部实例，禁改全局 `random` 状态。
- 为什么：hypothesis 自带种子管理，但测试里手写 `random.uniform` 造数据
  时不定种=失败用例不可复现；污染全局 random 还会波及同进程其他测试。
- 绑定：contracts/unit_api.py R1、units_lib/_template/compute.py R4
  （禁随机/时钟）既有；trace/calcbook.py R4（时钟取三元组）；
  本条新增——测试侧定种细则。

### GR-18 聚合求和顺序固定（按标识符排序后求和）
- 规则：多股聚合（汇流 ΣCi·Qi、泥量加和、成本汇总）的浮点求和必须先按
  稳定键（PortRef / 字段 ID / 单元 ID）排序再求和；禁止按 dict/set 遍历
  序直接累加。
- 为什么：浮点加法不满足结合律——求和序变化只在末位产生差异，恰好够
  打破"双跑字节级相同"（GR-01）且肉眼查不出；这是字节级确定性最隐蔽
  的破坏者。
- 绑定：本条新增——graph/propagate.py 规格未写求和序；graph/executor.py
  R3（双跑字节级相同）是其上游要求；trace/collector.py R2（固定迹序：
  工况→拓扑层→单元→公式）为同构既有样例。

### GR-19 时间戳一律 UTC ISO 8601，禁本地时间字符串
- 规则：序列化中的时间戳（view 态等）统一 UTC + ISO 8601（含 Z）；
  禁本地时间字符串、禁"YYYY/M/D"自由格式；时间戳永不进 design 态与
  content-hash。
- 为什么：本地时间字符串跨机排序错序、跨时区同名不同刻；一旦进哈希，
  同一设计在两台机器得到不同 content_hash，可复算三元组（AGENTS §12）
  从根上失效。
- 绑定：contracts/project_schema.py R4（design 态禁时间戳）、project/io.py
  R2（时间戳只在 view 态）既有；本条新增——view 态时间戳的格式沉默
  （已登记 UF-27）。

## 5. API/契约演进

### GR-20 三类稳定标识永改不弃
- 规则：formula_id / condition_key / 异常消息文本（GR-09）三类标识
  **永改不弃**——不改语义、不改文本形态；演进只能新增，不能重定义。
- 为什么：三者分别是计算迹、结果索引、审计对照的主键（result_schema
  R5：任一数值回溯到公式 ID+条文）；重定义其一=历史结果与计算书全部
  失配，且是静默失配。
- 绑定：contracts/condition.py R2（键格式样例逐字对照）、registry/
  formulas.py（formula_id 挂条文）、AGENTS §12（可复算三元组）既有；
  本条新增——三类并列的统一冻结规则。

### GR-21 字段只增不改语义，弃用走两版本
- 规则：契约字段只增不改语义；类型收紧/语义变更 = 新键 + 旧键弃用
  **两版本**过渡；弃用必须在 file-contracts.md 登记备注（含替代键与
  移除里程碑）。
- 为什么：前端客户端由 OpenAPI 生成、结果按字段 ID 消费（AGENTS §4）——
  直接改语义=新旧客户端同键不同解，且概算/图纸按旧口径取数无任何报警。
- 绑定：contracts/result_schema.py R1（变更走 ADR+契约测试+前端重新
  生成三步）、registry/dimensions.py R3（field_id 只增不改名）、
  AGENTS §2（file-contracts 双向校验）既有；本条新增——弃用流程与
  登记位。

### GR-22 schema 只增字段必须伴 format_version 递增与迁移链覆盖
- 规则：project_schema 增字段必须 format_version +1 并在 project/
  migration.py 迁移链补一步；禁"旧版本宽容解析新字段"的过渡写法
  （pydantic extra=forbid 下旧版读新文件=拒绝，这是设计而非事故）。
- 为什么：双态 schema 的严格模式（R2）与"字段只增"叠加后，唯一安全
  通道就是版本迁移链——绕开它做的宽容解析会在某次升级把宽容本身
  变成双源。
- 绑定：contracts/project_schema.py R2/R5、project/migration.py
  （链式纯函数迁移）既有；本条新增——增字段的版本纪律。

### GR-23 公开符号废弃 = 显式 commit + 调用方清点
- 规则：移除包公开符号（单元包 `__init__` 白名单内的名字）必须独立
  commit，说明动机并附调用方清点（grep 证据）；禁止顺手删。
- 为什么：单元包对外只暴露白名单名（AGENTS §11），跨包只走正门——
  白名单收缩是全仓接口事件，"顺手删一个没人用的名字"会在别人的
  分支上变成构建失败。
- 绑定：AGENTS §11（manifest+compute 两名白名单）、§2（file-contracts
  双向校验）、§9（共享状态串行）既有；本条新增——废弃流程化。

## 6. 命名

### GR-24 布尔用 is_/has_/allow_ 前缀，禁否定布尔
- 规则：新增布尔名用 `is_/has_/allow_` 前缀；禁否定布尔（`no_filter` →
  `allow_filter` 取反）；既有冻结 DSL 名（如 `pool.all_pools`）不回改。
- 为什么：双重否定（`if not no_filter`）是条件语义 bug 的头号温床；
  工况映射 DSL 表达式里出现双重否定时，评审几乎不可能逐条心算正确。
- 绑定：本条新增——填补代码命名沉默；contracts/manifest.py 工况映射
  DSL（T0.5 冻结正典 `pool.all_pools`）为不回改的既有冻结名。

### GR-25 单位不进变量名
- 规则：变量/字段名不携带单位后缀或单位缩写（`q_m3s` 禁）；内核一律
  裸值 + DimKey 语境，单位只出现在显示层字符串与序列化的显式 unit 字段。
- 为什么：名字里的单位是第二份单位真源——ADR-002 已把单位钉在
  quantity/dimensions 注册表，名字再带单位就会在单位换版时变成谎言
  （病灶"P_sludge 标 kW"即此类）。
- 绑定：ADR-002、contracts/quantity.py R4（数值+显式 unit 字段）、
  AGENTS §3 单位规则既有。

### GR-26 标识符字符集：ASCII 字母数字下划线
- 规则：标识符（unit_id / field_id / condition_key / 参数键 / 假设键 /
  系数库键）只允许 ASCII 字母/数字/下划线；禁中文、空格、斜杠进标识符
  （中文名只存在于 i18n 显示层；表达式内的点式引用是引用语法不是标识符
  构成）。
- 为什么：中文/空格/斜杠进键后，condition_key 拼接、文件命名、URL、
  CLI 参数四处都要转义——每一处转义规则又是一处未定义行为。
- 绑定：contracts/condition.py R2（unit_id 禁止含空格/斜杠）为既有
  单点样例；AGENTS §4（概算/图纸按字段 ID 取数、禁中文模糊匹配）；
  本条新增——推广为全类标识符通则。

## 7. 测试惯例

### GR-27 断言必须检验行为，不只"不抛"
- 规则：`pytest.raises` 用例必须断言异常消息中的键（unit_id/condition_key/
  参数键，GR-09 三元组）；正常路径用例必须断言产出值，"跑完没炸"不算
  断言。
- 为什么：不验消息的异常测试在异常类型被换、消息丢上下文时照样绿——
  恰好放走对诊断面板最致命的回归。
- 绑定：AGENTS §6 既有红绿纪律；本条新增——断言质量门槛。

### GR-28 一个测试一个断言主题
- 规则：一个测试函数只验证一个断言主题（一条行为规格 R 条）；多主题
  拆分用例；共享准备逻辑进 fixture（GR-29）。
- 为什么：多主题用例失败时报告只说哪个函数红，不说是哪条规格被破坏——
  镜像测试与规格头 R 条的一一对应（AGENTS §5/§6）就是在这里失效的。
- 绑定：AGENTS §6（镜像命名：规格↔测试）、§5（规格说明节逐条冻结）
  既有；本条新增——用例粒度规则。

### GR-29 fixture 用构造器/工厂，禁大段复制粘贴
- 规则：测试数据构造一律走构造器/工厂函数（如 make_flow 式正门），
  禁在每个用例复制粘贴字面量结构体；32 个单元包镜像测试共用
  unit_api 测试模板。
- 为什么：契约字段演进（GR-21）时，散装字面量要改 300 处且必然漏——
  漏掉的用例从此测的是旧契约，测试套件开始说谎。
- 绑定：contracts/unit_api.py 测试要求（协议结构契约模板供 32 单元包
  镜像套用）、contracts/flow.py（make_flow 唯一构造正门）既有；
  本条新增——测试侧数据构造纪律。

### GR-30 性质测试四模板：守恒/单调/往返/结合
- 规则：性质测试从四模板取材——守恒律（Σ 进 = Σ 出）、单调性（输入增
  → 输出不减）、往返恒等（parse→attach→parse 无损）、结合律（汇流
  混合的结合律 = business-logic §3 守恒的具体化）；新单元 properties.py
  至少挂一条守恒或单调。
- 为什么：这四类性质恰好对应本项目的四类历史病灶（守恒破坏/方向错/
  单位换算损/汇流序敏感）；性质测试是唯一能在随机输入上抓"规格没写到
  的组合"的层（AGENTS §6 hypothesis）。
- 绑定：business-logic.md §3 守恒断言点表、AGENTS §6（性质测试独立
  文件 properties_*）、quantity.py 测试要求（往返恒等）既有；
  本条新增——四模板选型。

## 8. 调试纪律

### GR-31 先复现→二分归因→根因修复→回归固化，禁 shotgun
- 规则：修复流程固定四步：先复现（最小用例/输入）→ 二分归因（注释/
  断点/最小化）→ 根因修复 → 回归测试固化（先红后绿）；禁"顺手改到绿"
  （shotgun：同时改多处直到测试变绿）。
- 为什么：shotgun 的本质是把"不知道为什么坏"升级成"不知道为什么好"——
  下次同根因复发时，之前乱改的部分全成干扰项；本仓锁定测试与门禁密度
  下，乱改的代价还要乘上审查成本。
- 绑定：AGENTS §8（每次改动一个逻辑单元、diff 自查范围蔓延）既有；
  本条新增——修复流程四步法。

### GR-32 修复必须附"为什么这是根因"一句话
- 规则：缺陷修复 commit/报告必须附一句话说明"为什么这是根因"（因果链：
  症状→机制→根因），不能只写"修复 XX 问题"。
- 为什么：无因果链的修复在三个月后会被当成可回退项/可复制的模式——
  若当初其实是误修复（症状消失但根因仍在），后人无从察觉。
- 绑定：AGENTS §8（提交信息中文描述意图）既有；本条新增——缺陷类
  commit 的因果链要求。

## 9. 日志与可观测（M2 前置）

### GR-33 日志是结构化事实，不是叙事文本
- 规则：日志一律结构化键值（事件名 + 字段），非叙事长句；计算失败的
  日志必须可重放定位——含三元上下文（unit_id/condition_key/参数键，
  GR-09 同一组键）与 design_hash；内核不含日志库，计算期事实走领域异常
  与计算迹，结构化日志住 server 层（AGENTS §1：内核禁 import 服务层
  依赖）。
- 为什么：叙事日志（"混合时好像出了点问题"）无法被检索聚合，也无法
  与 task_id/condition_key 对账；计算失败若不能重放定位，"可复算"
  承诺（AGENTS §12）在运维侧就是空话。
- 绑定：server routers/events.py R1（事件 JSON 化 {type, task_id,
  percent, message, condition_key}）为既有样例；AGENTS §3（禁静默）、
  §1（分层）既有；本条新增——M2 前置的日志形态规则。

### GR-34 内网工具不脱敏，但禁整段项目数据倾倒
- 规则：内网部署下日志/诊断输出不要求脱敏；但禁止把整个输入对象、
  全部参数表、整段计算迹倾倒进单条日志——引用 design_hash/单元/工况
  键即可定位重放。
- 为什么：倾倒的代价不是泄密而是淹没——一条 2MB 的日志会让同屏的真
  错误（三元组）不可见；且 trace 本有正式载体（result_schema.trace），
  日志里复述一遍就是双源。
- 绑定：本条新增——M2 server 实现前的日志边界；trace/collector.py
  R4（万级枚举采样入迹）为"控制输出量"的同构既有决策。

## 11. 分层与运行时契约（SENS 批 B 裁决落盘 2026-08-23）

### GR-36 L0 契约层准入判据：三类之一，禁 I/O 与可变状态
- 规则：进 L0 者须为三类之一：①冻结数据 schema；②跨层协议（结构/
  行为契约）；③被 ≥2 个非 L4 层共同消费的受限 DSL 内核或量纲/单位
  真源。禁含 I/O、禁运行时可变状态；file-contracts 该行须注明类别。
- 为什么：L0 现混合 schema/协议/DSL/引擎/真源多类内容——任何"多
  下层都要用"的共享物都有理由自称该下沉 L0，每件单独看都合理，
  累积即成垃圾抽屉层（commons 温床）；三类清单把"能不能进 L0"从
  逐案直觉变成可判定的准入判据。
- 绑定：AGENTS §1/§2、UF-34；本条新增——填补 L0 准入沉默。

### GR-37 向量化 compute 数值域错误载体：局部 np.errstate 承接
- 规则：向量化 compute 数值域错误载体——compute 数值路径以局部
  `np.errstate(divide="raise", over="raise", invalid="raise")` 上下文
  承接（GR-02 的执行载体）；算后 isfinite 守卫仅作二道网。口径分界：
  GR-02 管量与守恒路径零 NaN/Inf；enumerate 结果表 NaN 标注列是
  **终态数据**非中间量，不违 GR-02。
- 为什么：numpy 默认对 0/0、溢出只发 warning 且值继续传播——恰是
  GR-02 要禁的静默路径；载体不钉死则三个候选（errstate 上下文/
  isfinite 守卫/where= 分母保护）运行时行为不同，实现者随手选，
  NaN 政策在向量化路径上落空。
- 绑定：GR-02、UF-36；本条新增。

### GR-38 一切落盘产物原子写：临时文件+同分区 rename
- 规则：一切落盘产物（项目文件之外含导出物/arrow/临时件）临时文件+
  同分区 rename 原子落盘（推广 project/io.py R4）；产物留存上限与
  清理策略属 settings 配置，T4 实现时冻结数值。
- 为什么：原子写目前只有 project/io.py R4 一处先例——导出物/arrow
  半截文件可被消费（幂等重导出"覆盖"若非原子，崩溃瞬间留下半截
  产物且无报警）；留存无上限则磁盘无界增长。
- 绑定：io.py R4、UF-38；本条新增。
