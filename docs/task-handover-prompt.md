# 任务接手提示词（任何 AI/人接手任何任务的标准入口）

> 使用说明：**复制下方模板块**，替换【】占位符后作为任务的开工指令发给执行者
> （AI 或人）。它把宪法（AGENTS.md §0 阅读顺序）、惯例（工程常识默认答案）、
> 未定义特性登记（防自创语义）与五层规约拼成一条强制动线——照走即合规，
> 不依赖执行者自觉。本页自身不承载规则，规则以被引用文件为准。

## 模板（复制即用）

```markdown
【任务：<一句话任务名>】（任务 ID：<如 T6>；简报：<路径，仓库外 .workflow/briefs/>）

按以下顺序接手，任何一步不满足先停下报告，不带疑虑开工：

1. 读宪法 `AGENTS.md`——全部硬规则由 CI 强制，违反即失败；
   先执行 §0.1 技能盘点（枚举当次会话可用技能，逐项"用/不用+一句理由"，
   落盘 .workflow/skills-inventory-<任务ID>.md，未盘点不开工）。
2. 读 `docs/engineering-conventions.md`——规格沉默处的默认答案：
   沉默即按惯例，不自创。已拍板条目（【已拍板】标记）不得改义。
3. 读 `docs/undefined-features-register.md`——遇到登记项严格按"处置"执行
   （已定义→GR-xx 或既有规格条款——指向既有规格时注明文件与条号；
   待定义→随任务冻结，本任务若负责冻结则首条产出即冻结它；
   显式不做→按登记理由不实现；领域专家待拍板→列入问题清单上报，
   不代办）。
   **发现新未定义项：先登记（标
   "疑似"）再继续，禁止就地自创语义**；sweep 新登记项必须 grep 验证
   "规格确实沉默"并附命令摘要。
4. 按涉及面读对应文档（只读涉及的，不全读）：
   - 动哪个文件 → `docs/file-contracts.md`（职责表，新文件先登记）
   - 依赖/调用链 → `docs/structure-graph.md`（改依赖先改图谱 §1）
   - 单元间业务规则 → `docs/business-logic.md`（参数链/耦合归属/守恒/可行解）
   - 已拍板决策 → `docs/adr/`（ADR-001~009，索引见 mkdocs nav）
5. 读目标文件头部"规格说明"节 + 对应镜像测试（core/tests/**/test_*.py，
   只读锁定）——这是正确行为的定义；实现必须满足规格，不得反向迁就。
6. 任务简报（五层规约，占位由派发方填全）：
   - 行为层：【功能点，可验收的动词句】
   - 接口层：【签名/数据模型，粘贴关键签名】
   - 架构层：【复用模块路径+函数名；新文件位置+先补 file-contracts】
   - 生命周期层：【扩展点/明确不做的事】
   - 文化层：【错误处理/日志/测试先红后绿等约定】
7. 完成定义（DoD + 验证矩阵，占位由派发方填全）：
   - 【DoD 清单：逐项打勾后才算完成（AGENTS §10）】
   - 【验证矩阵：哪个行为→哪条测试/哪个门禁证明】
8. 红线清单（违反任何一条=返工重来）：
   - 禁改 core/tests/、server/tests/ 下任何文件（只读锁定，AGENTS §7）；
   - 禁编造/手改数字：公式基准只来自 docs/norms 条文摘录+手算对照表；
   - 门禁全绿：PYTHONUTF8=1 python scripts/run_gates.py；pytest 基线不回退；
   - 单 commit 单目的，中文意图；git diff --stat 无范围蔓延；
   - 惯例与规格冲突时以既有规格为准，冲突登记 register 并上报，
     不擅自改规格/门禁/ADR；
   - 拿不准=报 NEEDS_CONTEXT 停，不猜。

完成后：报告写到 E:\class\智水蓝图\.workflow\reports\<任务ID>-impl-report.md
（仓库外），附规格冲突清单（若有）与新登记项说明（若有）。
```

## 附：会话工作区 .workflow/ 说明（仓库外，跨会话持久）

仓库外的 `E:\class\智水蓝图\.workflow\` 是会话工作区，**不属于 git 仓库**，
其产物跨会话持久、按任务 ID 组织：

| 目录/文件 | 内容 |
|-----------|------|
| `briefs/` | 任务简报（需求唯一源，五层规约落成文） |
| `reports/` | 实现报告（含规格冲突清单、疑似项说明）、双审（DS/GLM）产物 |
| `review-unified.md` | 架构审查统一问题清单（register 种子项出处） |
| `skills-inventory-<任务ID>.md` | §0.1 技能盘点落盘（每任务一份，不缓存复用） |
| `ledger.md` / `workflow.md` | 台账与流程记录（审计链产物） |

- 产物写入 .workflow 不计入 git diff，不会污染"单 commit 单目的"自查；
- 报告里的数字（测试数/覆盖率）以 CI 输出为准，文档不手写（AGENTS §4）；
- 跨会话续作：先读对应 brief + report，再走本提示词动线。
